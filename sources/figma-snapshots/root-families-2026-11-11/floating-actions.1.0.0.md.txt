# FLOATING-ACTIONS-001 · Floating Actions 1.0.0

### REQ-SCOPE

Floating Actions reúne un resumen de selección y una región de acciones. La referencia visual es Laboratorio 27:5129 y el destino es Blue Heart DS. La vista inicial reproduce 1024 × 96 px, con datos de ejemplo.

### REQ-API

Label y Select all son textos editables. Show select all permite ocultar el enlace. Selected count es una instancia expuesta de Dot count/large/neutral, con muestra inicial 3. General actions es un Slot horizontal nativo de 0..n. Sus cuatro botones, el divisor y el cierre son contenido inicial del Slot y pueden sustituirse, eliminarse o reordenarse desde cada instancia.

### REQ-LAYOUT

Barra horizontal con dos regiones FILL de 488 px en el ejemplo, padding 24, radio 16 y alineación vertical centrada. El resumen usa gap 8; General actions usa gap 16. El divisor visual mide 1 × 48. Mantener sombra de radio 4, offset (4, 6), expansión 0 y color shadow-md. El host proporciona ancho suficiente para los textos y acciones. La barra no añade saltos ni desbordamiento automático.

### REQ-COMPOSITION

Reutilizar Dot oficial con color neutral, Button/text large default con icono PlusCircle Outline Light y un Icon Button/ghost large default con X Outline Light de Phosphor. El set original de cada dependencia conserva la propiedad sobre sus interacciones y tokens. Las acciones y el cierre permanecen dentro del Slot como en la referencia.

### REQ-THEME

Superficie blanca, contador neutral y demás detalles fijos. El texto del enlace de selección sigue el semántico de marca de cada tema. Label usa neutral-maximum, el neutral más oscuro del sistema para sustituir el negro literal de la referencia. Todos los colores se enlazan a la capa semántica con tokens de componente.

### REQ-TOKENS

Usar 19 firmas propias en component/floating-actions. Radio y offset horizontal de sombra comparten firma. Heredar los colores y tamaños de Dot, Button e Icon Button desde sus instancias. El registro no requiere primitivas ni semánticos adicionales.

### REQ-BEHAVIOR

En Figma el contador y los textos se editan manualmente. El host decide cuándo mostrar la barra, qué se selecciona, qué ejecutan Seleccionar todos y las acciones, y cómo se cierra. La barra no calcula conteos ni contiene destinos de prototipo propios. Los botones conservan el comportamiento de sus principales oficiales.

### REQ-A11Y

El host nombra las acciones e identifica el cierre, gestiona teclado y foco y anuncia los cambios de selección cuando corresponda. El enlace subrayado conserva una señal adicional al color. Comprobar contraste de las combinaciones propias en los cuatro temas.

### REQ-QA

Validar geometría de referencia, bindings de texto, superficie, espaciado y sombra, cuatro modos, dependencias oficiales y el Slot desde una instancia. Acreditar por separado edición de texto, inserción, retirada y reordenación de acciones.
